# NEFT — карта вышек и аналитические панели

Обновление подготовлено на основе присланных `app(1).py`, `train_model(1).py`,
`kaggle1(1).csv`, `condition_pipeline.joblib` и `condition_metadata.json`.
Сохранены тема проекта, авторы, подключение модели, ручная диагностика и важность признаков.

## Запуск в PyCharm

Распакуйте весь архив. Откройте папку, в которой находятся `app.py`, `fleet.py`
и `neft_core.py`. Выберите интерпретатор прежнего проекта, где уже работала модель.

```bash
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Не запускайте `python app.py`. Адрес приложения после запуска: `http://localhost:8501`.
Не копируйте только `app.py`: ему нужны `fleet.py`, `neft_core.py` и папка `assets`.

`requirements-ui.txt` устанавливает только интерфейсные зависимости и намеренно
не обновляет scikit-learn, NumPy или pandas. Версии вашего окружения обучения
записаны в `models/condition_metadata.json`; модель требует совместимого окружения.
При несовпадении версии scikit-learn приложение сообщает об ошибке, а не скрывает её.
Для другого окружения требуется отдельное повторное обучение вашим `train_model.py`.
Автоматического переобучения при запуске сайта нет.

## Что добавлено

- Между заголовком проекта и ручной диагностикой — интерактивная карта с иконками вышек.
- Поиск по идентификатору и названию, фильтры сигнала и материала, масштабирование.
- Карточка объекта: параметры из CSV, результат модели, замечания к данным.
- По щелчку на вышку или номер в таблице выбирается объект и заполняется форма ниже.
- Карточки количества объектов и сигналов; графики состояния, потери толщины и материалов.
- Вкладки «Аналитика», «Сигналы», «Реестр» с таблицами и выгрузкой CSV.
- Отметка «Принят в работу» не снимает сигнал и не изменяет исходные данные.
- Через «Загрузка реестра» можно загрузить другой CSV и нажать «Показать на карте».

Сводки строятся по текущим фильтрам. Карта показывает 30 объектов на странице
(15 на узком экране); переключатели страниц не исключают остальные объекты из
аналитики. Графики и числа не захардкожены: они формируются из записей и прогнозов.

## Источник данных и карта

По умолчанию используется `data/kaggle1.csv`. Все 1000 записей доступны в реестре.
В исходном наборе нет идентификаторов и координат скважин. Поэтому имена
`СКВ-0001`, `СКВ-0002` и т. д. — условные обозначения строк, а расположение вышек —
интерфейсная схема, не реальное месторождение. Карта не используется для навигации.
Параметры записей не дорисовываются, не обрезаются и не заменяются.

Если рядом есть `data/wells.csv`, приложение предпочитает его.
Также поддерживаются `data/kaggle1(1).csv`, `kaggle1.csv` и `kaggle1(1).csv`.
Для собственного реестра нужны те же десять признаков модели:

```text
Pipe_Size_mm,Thickness_mm,Max_Pressure_psi,Temperature_C,
Corrosion_Impact_Percent,Thickness_Loss_mm,Material_Loss_Percent,
Time_Years,Material,Grade
```

`Condition` может присутствовать, но во входы модели не попадает.
Дополнительные поля: `well_id` (уникальный), `well_name`,
`latitude` и `longitude` (только вместе). При наличии координат строится
координатный план без интернет-подложки. Поддержки спутниковых снимков нет.

Новые данные поступают из CSV после «Обновить данные» или явной загрузки нового файла.
Приложение не подключено к датчикам; временные ряды и «живые» замеры не генерируются.

## Интерпретация сигналов

Зелёный, жёлтый и красный — классы сохранённой модели после проверок входов.
Серый — требуется проверить данные: например, потеря толщины больше исходной
толщины, некорректное число или выход за обучающий диапазон.
Класс модели и замечания сохраняются отдельно. Поэтому количество красных
сигналов не обязано совпадать с числом строк с исходной меткой Critical.

Вероятности берутся из `predict_proba` с учётом порядка `classes_`.
Они не калиброваны и не являются подтверждённой вероятностью аварии или ремонта.
Модель классифицирует состояние образца трубы; она не определяет безопасное
время останова буровой установки. Приложение не отправляет команды оборудованию.
Решение об остановке принимает ответственный специалист по регламенту объекта.

Ручная диагностика — отдельный расчёт. Она не перезаписывает реестр и не меняет
сигналы карты. Отметки принятия сигнала хранятся только в сессии браузера и теряют
силу при изменении параметров объекта или файла модели; это не постоянный журнал.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты используют отдельную модель в памяти. Ваш файл модели не переобучается
и не перезаписывается. Границы выполненной проверки перечислены в `TEST_REPORT.md`.

## Git

Присланный `.gitignore` сохранён; он исключает `data/`. Поэтому папка с датасетом
сама не попадёт в коммит. В рабочем проекте данные должны оставаться локально.

```bash
git add app.py neft_core.py fleet.py assets .streamlit requirements-ui.txt README.md TEST_REPORT.md tests
git commit -m "Добавлены карта вышек и дашборды мониторинга"
git push
```
